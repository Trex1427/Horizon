# Horizon v1.0 Beta

Etat

- En cours

Date

- 2026-07-12

Version precedente

- Aucune

## Objectifs

- etablir une premiere beta exploitable sur le socle Horizon;
- stabiliser les modules coeur de gestion financiere;
- disposer d'une base technique maintenable pour les referentiels, l'import bancaire et les evolutions analytiques futures.

## Nouvelles fonctionnalites

- module Transactions avec creation, mise a jour et suppression logique;
- module Objectifs;
- module Frais fixes;
- module Revenus recurrents;
- module Budgets;
- module Previsions;
- module Categories;
- cockpit Horizon et synthese dashboard;
- support des transferts internes via une collection dediee `transfers`;
- premiere fondation d'import bancaire CSV avec preview, doublons, validation et commit Firestore;
- scan de ticket par Cloud Function `parseReceipt` avec generation de brouillon;
- parsing vocal de brouillon de transaction;
- premiers referentiels distincts pour sous-categories, activites, tiers et projets.

## Corrections

- durcissement des seeds categories et comptes pour eviter une recreation apres suppression volontaire;
- prise en compte des transferts dans les calculs de soldes sans impacter le patrimoine net global;
- neutralite explicite de la suggestion de categorie import afin de ne pas deduire automatiquement une categorie a partir d'un marchand ou d'un tiers.

## Ameliorations UX

- dialog transaction disponible;
- `EntityFormDialog` generique deja utilise par plusieurs formulaires hors transaction;
- adaptation mobile de plusieurs dialogs en plein ecran;
- actions de masse sur transactions presentes via `TransactionBulkEditDialog`;
- revue de brouillon ticket disponible via `TransactionDraftReviewDialog`.

## Changements techniques

### Architecture

- structuration frontend en pages, hooks, services, utils, context et features;
- centralisation des calculs transverses dans `src/services/financeCalculations.js`;
- isolation du domaine transferts dans `src/features/transfers/`;
- isolation du domaine import bancaire dans `src/features/bankingImport/`.

### Firestore

- Firestore confirme comme source de verite;
- abonnements temps reel generalises via `onSnapshot` dans les services;
- CRUD principal en services dedies;
- lots Firestore utilises pour l'import bancaire et certaines mises a jour de masse.

### Cloud Functions

- Cloud Function HTTP `parseReceipt` deployee pour l'analyse de tickets;
- integration d'un appel OpenAI Vision cote backend uniquement.

### Import bancaire

- detection multi-format presente;
- pipeline complet actuellement expose seulement pour le CSV;
- OFX, QIF, PDF, CAMT.053 et MT940 encore en placeholder ou non exposes jusqu'au commit.

### Referentiels

- categories actives;
- sous-categories, activites, tiers et projets deja presents comme collections et services dedies;
- architecture de referentiels deja separee, mais UX de gestion encore inachevee selon la roadmap.

## Migrations eventuelles

- aucune migration obligatoire identifiee a ce stade pour utiliser le socle actuel;
- des migrations opportunistes non destructives restent envisageables plus tard, notamment pour enrichir certains anciens enregistrements avec des identifiants de referentiels.

## Compatibilite

### Compatibilite des donnees

- compatibilite legacy maintenue pour certaines transactions via `categorie`, `categoryName`, `categoryId`, `legacyType` et `needsTypeReview`.

### Compatibilite Firestore

- compatible avec le schema actuellement exploite par les services Horizon;
- coexistence encore presente de conventions de suppression logique differentes (`isActive` et `isDeleted`).

### Compatibilite Android

- support mobile present dans l'UI;
- un point de vigilance connu subsiste sur les timeouts OCR Android.

### Compatibilite Web

- application web React + Vite active;
- build indique comme OK dans la documentation projet.

## Dette technique restante

- convention de suppression logique non unifiee;
- couverture de tests encore insuffisante hors calculs et services deja testes;
- taille de bundle elevee au build;
- import OFX encore indisponible en flux complet;
- uniformisation incomplete des dialogs et formulaires;
- validation fonctionnelle reelle encore en cours pour la beta.
