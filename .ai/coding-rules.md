# Coding Rules

These rules guide all development on Budget Alexandre.

## Core principles

- Never break an existing feature.
- Always propose a plan before any significant modification.
- Modify only the files that are strictly necessary.
- Verify errors after each evolution.
- Keep the code readable, clear, and maintainable.
- Avoid duplicated logic.
- Prefer small, focused, reusable components.

## Technical constraints

- Use Material UI for the interface.
- Keep Firebase and Firestore as the backend foundation.
- Preserve real-time updates where relevant.
- Favor clean architecture over quick fixes.

## Working style

- Write code that can evolve over time.
- Comment only when the intent is not obvious.
- Keep responsibilities separated.
- Prefer stable and predictable behavior over shortcuts.
